# Check observations

Run `npm run check:preflight` with Node.js 22.16.0 or newer and `TEST_DATABASE_URL` set to a disposable PostgreSQL 16 database. The preflight verifies connectivity, the server version and schema permissions in a rolled-back transaction. It never prints the connection string. Focused `npm test -- test/<file>.test.ts` remains usable without PostgreSQL; skipped integration suites in that command do not establish release readiness.

Install the pinned browser once with `npx playwright install --only-shell chromium`; Linux CI uses `npx playwright install --with-deps --only-shell chromium`. The required browser suite drives Chromium's virtual authenticator, parses its actual credential-creation response and verifies discoverable assertions, including missing UV and incorrect challenge/origin. Its small report and screenshot are under `.generated/wallet-observations/browser-required/`. It persists no credential, assertion or private key. This checks the browser producer and server boundaries, not shared-wallet UI or physical-device compatibility. Browser absence fails the required suite instead of silently skipping it.

`npm run check` runs that preflight, the existing pinned execution checks, passkey compatibility checks, MCP checks, typechecking, every service test and the build. Its service JSON report must contain every required database and execution suite, with nonzero tests and zero failures, skips or todos. A missing report fails the check, even if the child process exits successfully.

Each command prints an observation path under ignored `.generated/checks/<run-id>/`. `summary.json` records the revision, whether the working tree was dirty, start/end source fingerprints and times, the result, per-step exit status, per-suite test counts and relative log paths. Source fingerprints hash actual tracked and non-ignored untracked bytes and modes, including missing and newly staged paths; `dirty` compares those bytes and the index directly to HEAD blobs. Assume-unchanged, skip-worktree and clean filters cannot hide source differences. Symlinks contribute their link text, and their targets are never followed. A source change during the run fails attribution and requires a rerun. Summaries use a temporary file and atomic rename, preserving the previous complete observation when a write is interrupted. Logs redact URL values and recognized secret environment values, including JWTs and structured sponsorship authorization keys; summaries omit test arguments, assertion data and failure payloads. Full service/MCP JSON is read from a private temporary directory and deleted after summarization. Test fixtures must still avoid logging credentials or passkey assertions in arbitrary formats.

Each release step has a ten-minute deadline; expiry kills its process group, including hung descendants. An output-processing or log-write failure also stops the step. Output is bounded to 32 MiB per step and 1 MiB per line. These local bounds supplement the unchanged fifteen-minute CI job deadline. The required-suite inventory test independently checks all fourteen database-bearing files, including the ceremony store, enrollment crash/race suite, actual browser enrollment through two HTTP processes, and 100-request enrollment races. It also pins the WebAuthn, signature, Safe profile, onboarding, deployment approval, user-operation and actual EVM passkey suites. Each required file must appear with nonzero tests and zero skips; adding a required suite means updating the explicit registry and inventory together.

Use the loop: run the focused test to observe a failure, make the smallest fix, rerun that test, then run the release gate once the related changes are ready. Read the failed step's log and the suite counts instead of treating an exit code alone as evidence. A `running` observation left by a killed process is incomplete, and a successful `preflight` observation only proves prerequisites. A dirty-tree observation is development evidence; rerun against the final commit before making a release claim.

These local checks establish deterministic database and execution behavior. Device interoperability, hosted provider behavior, load, failover and production outcomes require the separate evidence gates in [the implementation strategy](CENTER-WALLET-PLAN.md).
